# E4 analysis code: readings taken where `prereg/E4.md` is silent

This document lists every reading that the E4 analysis code (`src/uc_e4`) takes where the registered text (`prereg/E4.md`, OSF dpxqf, SHA-256 `df7e2745b9f30dc9d9ed53526214f8d4f464f175f3180fcff3e1a92e4d03c7b9`) does not settle an outcome: the quotation, the options, the choice and the reason. Nothing here changes a registered rule. Where a reading decides whether the structure mapping stops, the reading that stops is preferred to one that lets an unsettled outcome pass, because a stop is settled by an amendment registered before any level is read (section 13). The entries are adopted in decision D-050 and are cited in the code by their numbers (R-G.1 and so on).

Labels: (a) verified by running the test named; (b) read from a named source at a named place; (c) inferred.

### General

**R-G.1 Development coordinates.** Development runs use a master seed other than 1927, stream ids from 9000 upwards and shortened counts, and are labelled development runs. Options: (i) reuse the registered stream ids under another master seed, as the E1 and E3 development runs do (`uc_ext.common.DEVELOPMENT_MASTER_SEED`); (ii) stream ids from 9000. Choice: (ii). `uc_e4.streams.check_run` refuses any registered id (100-105, 200-201, 300-301, 400-401, 1001, 1013, 2008, 2012, 5100-5431) with a development seed, and refuses master seed 1927 unless the caller passes `allow_registered=True` and the registered stream plan `REGISTERED_STREAMS` (5400, 5401, 5402, 5404, 5405, 5420, 5421, 5430, 5431; 5403 deliberately absent). Reason: a development run can then never consume a registered coordinate. The flag records that the caller has verified the gate (public registration, tag, X.3 record); this package cannot verify it. The generator builder `stream_rng` applies the same flag to the registered seed and to every registered id, so that a call which does not go through `check_run` is refused as well. (b) Annex A. Tested (a).

**R-G.2 Interpreter.** The development results cited here were obtained on Python 3.12.3 with numpy 2.5.3, pandas 3.0.6, scipy 1.18.1 and pytest 9.1.1, the versions of `requirements.lock`; registered runs use Python 3.12.14 under the lock. (a)

**R-G.3 Reuse of private helpers.** `uc_core.surrogate._integer` and `_generator` are used for argument checks, as `uc_core.h1` and `uc_ext.common` do. They are not changed. (b) `src/uc_ext/common.py`.

### Section 4: the availability-table model (`src/uc_e4/table.py`)

**R-4.1 Cell kinds.** Quotation (section 4, step 2): "*numeric*; *empty*; *marker*, a text containing no digit, such as "..", "-" or "x"; or *other*, any other content, such as a text containing a digit (including a number stored as text), an error value or a logical value." Options for cell values not named: whitespace-only text; the empty string; a non-finite number; a date. Choice: `None` and `""` are empty; any other text without a digit, including whitespace only, is a marker; an `int`/`float` (not a logical value) is numeric even if it is `nan` or `inf`, because section 5 handles a non-finite level ("A level in the run that is non-positive or non-finite makes the episode unavailable"); logical values, error values, dates and anything else are other. Reason: the literal text; a reader gives `''` for an empty xls cell and `None` for an empty xlsx cell, and both are empty. Alternative not adopted: whitespace-only text as empty. (a) `tests/test_e4_table.py::test_cell_kinds`.

**R-4.2 Error values.** A reader can deliver an error value as a text ("#N/A", "#DIV/0!" and so on) or as a typed error. Choice: `ErrorValue` (typed) and any text equal to an Excel error literal are kind other, so they stop the mapping. Reason: "an error value" is named as other; "#N/A" contains no digit and would otherwise be read as a marker. (a)

**R-4.3 "Digit".** Choice: any Unicode digit (`str.isdigit`), so a superscript or a non-Latin digit makes a text other. Reason: it stops rather than passes; the text says "no digit". (a)

**R-4.4 Vintage labels that parse.** Quotation (step 3): "A vintage label parses if it is a date or states a calendar month and year; its release month is that month." Choice: a `date`/`datetime`; or a text `YYYY-MM`, `YYYY/MM`, `MM/YYYY`, `YYYY-MM-DD` (with an optional time); or a text with exactly one month name (three letters or in full, "Sept" too) and exactly one four-digit year in either order, at most one day number of 1 to 31, and only the ordinal suffixes and "of" as other words. Not accepted: two-digit years ("Jan-16"), two month names ("Oct to Dec 2015"), a month without a year, other words or numbers ("Jan 2016 Month 2"), Excel serial numbers. Reason: an ambiguous label should stop for an amendment, not be guessed. (a) `test_vintage_labels_that_parse` and `..._do_not_parse`.

**R-4.5 Reference-quarter labels that parse.** Quotation: "A reference-quarter label parses if it states a calendar quarter." Choice: text only: `1955 Q1`, `1955Q1`, `1955-Q1`, `Q1 1955`, `1955 quarter 1`, `1st quarter 1955` (case and spacing insensitive); a date or a month name does not state a quarter. Reason: as R-4.4. (a)

**R-4.6 "Vintage ranges that do not overlap".** Quotation (step 1): "the parts are joined into one table, in the order of their vintage ranges, only when they hold vintage ranges that do not overlap and have identical reference-quarter labels." Options: open ranges (parts may share a boundary month) or closed ranges. Choice: closed ranges of release months [earliest, latest] of each part; sharing a month is an overlap and stops. Reason: two vintages of one release month in different parts would have no defined order (step 4 orders ties by position in one table). (a) `test_table_split_across_two_sheets_not_joinable`. Consequence to note: a workbook whose sheets meet at a shared month would need an amendment.

**R-4.7 "Identical reference-quarter labels".** Choice: the same sequence of label texts in the same order in every part (compared as given, no normalisation). Reason: literal; a difference in spelling of the same quarter stops. (a)

**R-4.8 Join order and direction.** Quotation: "in the order of their vintage ranges". Choice: parts are joined in ascending order of range when their vintages ascend left to right, and in descending order when every part with a direction descends; a conflict is left to the step 4 rule, which then stops. The joined table keeps each part's internal column order. (a) `test_table_split_across_two_sheets_descending_parts`, `test_join_direction_conflict_is_caught_by_the_order_rule`.

**R-4.9 Order in which stops are found.** The text lists steps 1 to 4; if several stop conditions hold, the first in that order is raised (4.1 table and join, 4.2 a cell of kind other, 4.3 a label that does not parse or a repeated quarter, 4.4 direction). The vintage labels are parsed early only where the join needs them, and a label that does not parse there is a 4.3 stop. Reason: the result of a stop is the same (an amendment); the order fixes which reason is printed. (a)

**R-4.10 Direction, ties and degenerate tables.** Quotation (step 4): "Vintages are ordered by release month. Vintages with the same release month are ordered by their position in the table, read in the direction in which the release months increase. If the release months do not increase in one direction across the table, stop and amend". Choice: the release months, in table order, must be non-decreasing (read left to right) or non-increasing (read right to left) with at least one strict change; otherwise stop. A table whose release months are all equal, or with one vintage, stops: no direction of increase exists. Ties keep table order when ascending and reversed table order when descending. Reason: literal; such a table could not verify a first release anyway. (a) `test_release_months_that_do_not_increase_in_one_direction_stop`, `test_descending_table_is_read_...`.

**R-4.11 Levels held apart.** Choice: `build_tables` returns an `AvailabilityTable` (kinds, vintages, quarters, marker texts; no number) and a separate `LevelTable`; `availability_report` takes only the first, so it cannot print a level. Marker texts are printed as they are (they contain no digit by definition); a stop for a cell of kind other carries the content with every digit replaced by `#`. Reason: step 2, "It prints no level." (a) `test_report_prints_no_level_and_levels_are_held_apart`.

**R-4.12 What the package does not do (section 4).** It works on cell values, not on a file. Choosing the sheet or sheets that hold the vintage-by-quarter table, reading the workbook's cells (with the reader's own empty and error types), printing sheet names, titles and notes with numbers blanked, and the check that "its title, cover and notes ... name another edition or release date" (section 4, release rule; Annex B step 3, "a title or notes naming another edition") belong to the X.2 source stage (`src/uc_ext_official/e4_source.py`) and are not part of the code identity of the X.3 checks. (c)

### Sections 5 and 7: vintage series and eligibility (`src/uc_e4/vintage.py`)

**R-5.1 The run.** Quotation (section 5): "Take the levels in vintage v for the contiguous run of present quarters ending at q_j - 1. Start at the later of 1955Q1 and the first quarter of that run. A quarter before q_j - 1 with no level ends the run". Choice: walk back from q_j - 1 through quarters whose cell is numeric; stop at the first quarter with an empty cell, a marker or no row, or at 1955Q1 (the floor: nothing earlier is used even if present). A non-positive or non-finite value does not end the run; it is a stop for the episode if it lies inside the run after the floor, and is irrelevant outside it. n_v = number of levels in the run minus one (0 if fewer than two). Growth is `400 * np.diff(np.log(levels))`, the expression of `uc_core.abmi.growth`. (a) `tests/test_e4_vintage.py`.

**R-5.2 No level for q_j - 1 in a vintage.** The series is empty (status `no_level`); this cannot arise for v_j, by definition.

**R-7.1 Step 2, the first-release check.** Quotation: "The vintage immediately before v_j must exist, and must have no level for q_j - 1." Because v_j is the earliest vintage with a level for q_j - 1, the second condition holds by construction; only "must exist" can fail. The code still tests both (defensive) and reports failure at step 7.2. (a)

**R-7.2 Which step is reported.** Quotation: "All others are reported with the step that failed." Choice: the first step that fails in the order 1, 2, 3, 4 is the one reported (7.1 no vintage has the level, 7.2 first release unverifiable, 7.3 length, 7.4 a section 5 stop). A section 5 stop found in a series that already failed step 3 is recorded as a note (`stop_note`), not lost. (a)

**R-7.3 Episodes and their index.** The four H1 eligible episodes are read from the frozen record `audit/H1_RESULT.json` (`episodes` with `statistic_available` true): j = 0..3 for 1973Q3, 1980Q1, 1990Q3 and 2008Q2, checked against the four onsets of section 4, and never renumbered (section 7). Their `change` is Delta_final for the descriptive table only. (b) audit/H1_RESULT.json; (a) `test_h1_record_loader_checks_the_registered_onsets`. The record was read for these four rows only; no file under `data/raw/` was opened.

**R-7.4 Other windows.** Quotation (section 10): "Eligibility is n_v >= 40 or n_v >= 56 respectively." Choice: steps 1, 2 and 4 are unchanged; step 3 uses n_v >= W + 8 (48, 40 and 56). Each window has its own selection (`select_episodes(..., window)`), so an episode unavailable at W = 40 by length can be eligible at W = 32. (a)

### Sections 8 and 9: statistic, null and p (`src/uc_e4/procedure.py`)

**R-9.1 Position of the onset.** The onset of an episode is position n_v, one past the last position of its series. `uc_core.recession.pre_onset_changes`, `secondary.mean_pre_onset_trend` and `signed_pre_onset_changes` require an onset inside the series, so each is called on the modulus (or lag-one) path with one throwaway value appended and the onset n_v. No registered function reads the appended value (tested), so the registered functions are reused unchanged. Delta_rt = M(n_v - 1) - M(n_v - 9) agrees exactly with `pre_onset_changes` on a longer series (tested). (a) `test_delta_agrees_with_uc_core_rolling_modulus_and_pre_onset_changes`, `test_the_padding_value_is_never_read`.

**R-9.2 What fails the observed statistic.** Quotation (section 7, step 4): "A failed rolling fit, or a non-finite M_v at a position that Delta_rt requires, in the series of an E4-eligible episode is a failure of the observed statistic (H1 §§4-5): it fails the comparison and does not make the episode unavailable." Choice: the rolling modulus is computed over every window of the vintage series, as H1 and E1 do (`uc_core.rolling.max_modulus`); a window that cannot be fitted anywhere in the series fails the statistic (H1 section 4: "later nonfinite or unidentified windows fail the affected analysis rather than being treated as warm-up or silently excluded"). The episode stays E4-eligible, its Delta is missing, the primary comparison has status `observed_statistic_failed`, no null is fitted and no draw is made, and the episode interval is failed, not empty (H1 section 8). Alternative not adopted: computing only the two windows Delta needs. Reason: the fixed contract of `uc_core`, and identical surrogate semantics. (a) `test_failed_observed_statistic_fails_the_comparison_and_draws_nothing`.

**R-9.3 Failed null.** Quotation: "An unstable or failed null for any E4-eligible episode fails the comparison before any draw". Choice: all nulls are prepared first (`uc_core.surrogate.prepare_null`: intercept-inclusive OLS on all n_v values, strict stability, centred residuals); any `NullModelError` gives status `null_model_failed` with zero draws and no generator advanced. (a)

**R-9.4 Draws and failures.** Quotation: "draw n_v - 2 residual indices in one `integers(0, n_v-2, size=n_v-2)` call from the episode's own generator" and "Episodes do not share a generator, so one episode's failure cannot shift another's draws." Choice: attempt b draws for every episode in j order, each from its own generator, whatever happens in another episode; each episode's draw call is made before its recursion (`uc_core.surrogate.draw_surrogate`), so a failure later in the attempt cannot shift later attempts. A failed attempt is recorded, the remaining attempts continue for accounting, and p is invalid (H1 section 6). Every attempt is structurally eligible, so retained = B - failed and no attempt is coded "no eligible episode". K counts ties (`S_b >= S_rt`). q = K / B' and the Wilson interval are `uc_core.validation_design.wilson_interval`. (a) `test_draws_follow_annex_a_and_section_9_exactly` (an independent by-hand reconstruction of every attempt from `SeedSequence([seed, stream, j, 0])`), `test_one_episodes_generation_failure_cannot_shift_another_episodes_draws`, `test_one_episodes_draws_do_not_depend_on_another_episodes_data`.

**R-9.5 Streams.** Episode j uses `SeedSequence([seed, stream, j, 0])` (Annex A: cell j, replicate 0). The stream id is an argument (5400 registered; 9400 in development). (a)

**R-9.6 Shared paths.** Quotation (section 10): "Shares the stream 5400 paths." Choice: the Kendall and lag-one statistics are computed from the same generated paths as the primary in the same attempt, with their own eligible episodes and denominators; a failure unique to one statistic invalidates that statistic only, a generation failure invalidates all (H1 section 7). If the primary observed statistic fails but a comparator is computable, the paths are still drawn for it (H1 section 8: "continue any computable comparator"). (a) `test_kendall_and_lag_one_share_the_primary_paths_with_their_own_denominators`.

### Section 10: secondaries and descriptive tables (`src/uc_e4/analysis.py`, `src/uc_e4/descriptive.py`)

**R-10.1 Kendall and lag-one eligibility.** Kendall: an episode counts only if M_v(n_v - 16) exists (n_v >= W + 15, 55 at W = 40), as `uc_core.secondary.mean_pre_onset_trend` decides; constant segment is a failure of the statistic. Lag-one: the W = 40 windows (`rolling_lag1`), eligibility as the primary. Neither exists at other windows in the registered table, and the code computes them only for the primary window. (a)

**R-10.2 Episode interval.** As H1 section 7 over the m_E4 Delta_rt values (`episode_percentile_interval`, one `integers(0, m, size=(B, m))` call, linear quantiles), stream 5405 cell 0 replicate 0; B = 10,000 registered, an argument here. m = 0: no interval; a failed observed primary: interval failed. (a)

**R-10.3 Not estimable and Holm input.** Quotation: "If m_E4 = 0, E4 is not estimable. It is recorded as failed and enters DR-2 with Holm input 1". `analyze` returns `status` `not_estimable`, `raw_p` None and `holm_input` 1.0; a failed or undefined p also gives 1.0; otherwise the Holm input is the raw p. It does not apply Holm (family closure) and does not write the outcome wording of section 11 (X.5 tooling). (a)

**R-10.4 Real time against final.** Row per H1 eligible episode, unavailable ones included. Choice: difference = Delta_rt - Delta_final (the sign of the summary S_rt - S_final,m); "the number of episodes where the two have the same sign" counts episodes where both are positive or both negative (an exact zero has no sign and is not counted). Summaries only when every E4-eligible episode has a Delta_rt. (a)

**R-10.5 Release date and the end of q_j.** Quotation: "the release date of v_j, and whether it falls before the end of the onset quarter q_j". Choice: release dates are an argument (label to date, from ONS metadata); with a date the answer is `release_date <= last day of q_j`; with the label month only, earlier month than the quarter's last month is True, later is False, equal is "undetermined: label month only". Rows say which basis was used. Reason: the text gives the label month as the fall-back. (a)

**R-10.6 First vintage showing the onset.** Quotation: "the first vintage in which quarters q_j and q_j + 1 both show negative growth". Choice: the first vintage, in vintage order, that has positive finite levels for q_j - 1, q_j and q_j + 1 with both growth values strictly below zero ("none" otherwise); a vintage lacking a level for one of them does not show it. This reads levels after q_j - 1 only for this description. (a)

### Section 11: synthetic vintages (`src/uc_e4/synthetic.py`)

**R-11.1 The vintage series.** The synthetic series are growth-like values (H1's generating process), so each truncation is passed to the procedure as a growth series; no level table is built. Vintage r = positions 0..r-1, n_v = r = 49, 99, 149, 199, 249, all above the threshold 48. Generation is `uc_core.validation_design.h1_design_series` (the registered H1 generator; `uc_ext.common.design_series` is bit-identical to it, per the E1 tests). (a) `tests/test_e4_synthetic.py`.

**R-11.2 Coordinates.** Size: generation cell 0, replicate i; surrogates cell j (synthetic vintage 0-4), replicate i. Power: generation cell = kappa index, replicate i; surrogates cell = 10 * kappa index + j, replicate i. A rejection is a valid raw p <= 0.05. Summaries, the 0.02-0.09 band, the adjacent-difference flag and D80 use the E1/E3 shared functions (`uc_ext.common.summarize_size`, `summarize_cell`, `summarize_power_cells`), which reproduce H1's. A development run cannot pass. (a)
