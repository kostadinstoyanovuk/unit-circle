# E4 step X.2: select the edition, acquire it once, map its structure

This procedure implements Annex B step 2 of the registered addendum `prereg/E4.md` (OSF dpxqf): "Download the one real-time database edition under §4. Hash it and make it read-only. Run the header and availability mapping, and record the vintage coverage in the manifest." It runs on the research computer, in the registered environment, from a clean checkout of the research repository. Every stage fails closed. No stage reads or prints a level: the first reading of levels is the registered run (X.4), after the official synthetic checks (X.3). The readings that the stages apply where the text is silent are in `docs/E4_X2_READINGS.md` (R-X2.1 onwards).

## 0. Gates

- **G4 for E4**: the E4 runner's registration check (`tools/run_e4_checks.py`, `verify_extension_gate` and `gate_record`, called through `uc_ext_official.gates.check_registration`): a clean checkout, the annotated tag `prereg-E4` published identically on origin, `prereg/E4.md` equal to the tagged file, and `audit/E4_REGISTRATION.json` showing the approved public registration whose archived `E4.md` has the tagged bytes. Every stage that writes a record needs it, so every record must be committed before the next stage runs.
- **No X.3 record is needed** for X.2 (Annex B: the download precedes X.3). The level reader for X.4 (section 5 below) needs it.

## 1. List the editions and apply the release rule

Save the dataset landing page after the release of 30 September 2026, and the release-calendar record of that release, then list:

```text
python tools/acquire_e4.py list --fetch https://www.ons.gov.uk/economy/grossdomesticproductgdp/datasets/realtimedatabaseforukgdpabmi \
    --fetch https://www.ons.gov.uk/releases/<the record of the release of 30 September 2026> --pages-dir <pages directory>
python tools/acquire_e4.py list --dataset-page <saved landing page> --dataset-page <landing page of 29 September 2026> \
    --calendar-page <saved calendar record> [--requests-log <request log>]
```

The first form requests the pages now, through the address allow-list (R-X2.6: the two dataset landing pages, edition pages and release-calendar records only; never a data file or a `file?uri=` address), saves them with a request log in the pages directory, and evaluates them. The second form evaluates saved pages; a request log in the format of `audit/e4_source/guarded_fetch.py` supplies each page's address and retrieval time. Nothing is recorded in the repository.

The listing prints every edition, whether it is eligible and why, and any missing evidence. The registered rule (section 4): the latest edition released strictly before the verified public-registration timestamp, 2026-09-30T06:27:00.909545Z (07:27 UK time). An edition's release date comes from a dataset page on which it is listed first; its time of day from a published release-calendar record of that date that lists the dataset (R-X2.1). A release on 30 September 2026 needs that time: a release at 7:00am UK time (06:00 UTC) precedes the registration; without a stated time the edition is not eligible and the missing evidence is named (R-X2.2). The listing also says whether the saved pages exclude a later edition released before the registration (R-X2.4).

## 2. Select the edition

```text
python tools/acquire_e4.py select <the same page options> [--accept-missing-evidence]
```

Needs G4. Writes `audit/e4_source/edition.json` once: the registration timestamp, every page used (bytes and SHA-256), every edition considered with its evidence and eligibility, and the selected edition (label, file URL, release date, time and UTC instant where established). It refuses while the evidence is incomplete; `--accept-missing-evidence` records that the missing evidence named by the listing cannot be obtained, and is stored in the record (R-X2.5). If no edition can be established as released before the registration, or the latest cannot be identified, the stage stops before any value is read: the amendment is registered before any level is read (section 4 and section 13). Commit the record.

## 3. Acquire the workbook once

```text
python tools/acquire_e4.py acquire --download --licence "Open Government Licence v3.0" --licence-url <licence page>
python tools/acquire_e4.py acquire --downloaded-file <file>.xlsx --source-url <the selected file URL> \
    --retrieved-utc 2026-...Z --licence "Open Government Licence v3.0" --licence-url <licence page>
```

Needs G4 and the committed edition record. Accepts only the file URL of the selected edition's entry on the dataset page, and only an xlsx package (an error or challenge page is not the file). The retrieval must follow the verified public registration (`public_first_verified_at_utc`). The workbook is stored once, read-only, at `data/raw/E4_ABMI_realtime_<edition>.xlsx`, a git-ignored path: it is kept out of the repository, as the E1 workbook is (D-041). `audit/E4_ACQUISITION.json` records the edition label, release date and time, URL, retrieval time, size, SHA-256, licence, the edition record's SHA-256 and the gate; `DATA_MANIFEST.csv` receives one row (file, source URL, series, retrieval time, SHA-256, licence, and notes beginning "Not distributed in this repository"). A second acquisition is refused. Commit the record and the manifest, not the workbook.

## 4. Map the structure from headers and availability

```text
python tools/acquire_e4.py map
```

Needs G4, the committed acquisition record, and a workbook that is present, untracked, read-only and identical to its record. It does not need the X.3 record. Section 4, "Structure mapping at X.2", steps 1 to 5, from text cells and cell types only:

1. Sheet names and states (hidden sheets included); the document properties, titles, cover, notes and cell comments, with decimal numbers, percentages, currency amounts, thousands-separated numbers and numbers of five or more digits blanked as in Annex C (R-X2.12).
2. The check that the title, cover and notes name no other edition or release date than the selected one (R-X2.10).
3. The vintage-by-quarter table, found by parsing labels (R-X2.7, R-X2.8): its sheet, label column, header row, rows and columns; parts on several sheets joined only under the registered condition.
4. The vintage labels and reference-quarter labels; the availability per vintage (numeric, empty, marker, other: counts only), with marker contents and, at a stop, other contents with every digit replaced by `#`.
5. The labels parsed, the vintages ordered, and the earliest and latest vintage and the earliest reference quarter, which are added to the manifest row.

Each attempt writes `audit/e4_source/structure-attempt-<k>.json` and `.txt` once and a line in `audit/e4_source/structure-attempts.jsonl`. A completed mapping also writes `audit/e4_source/structure-mapping.json` and `.txt` once and updates the manifest row's notes with the coverage. Commit them.

**A stop.** The stage never proceeds past a stop: it records the step and the reason and exits non-zero with "stop and amend (section 13)". A stop is not a deviation; it is settled by an amendment registered before any level is read. After a stop under the release rule (another edition or release date named in the title, cover or notes), the amendment states which file is used. After any other stop at the structure mapping, the workbook already acquired is kept and used. Once the amendment is registered and its record committed, and any code change that it requires has been made with a test, the mapping is run again, naming the record:

```text
python tools/acquire_e4.py map --amendment audit/E4_AMENDMENT_1.json
```

## 5. Levels for the registered run (X.4)

`uc_ext_official.e4_source.read_level_tables(root)` builds the level table, held apart from the availability table, from the cells that the committed mapping records. It needs G4, the committed X.3 record (`audit/E4_X3.json`, passed), the frozen code (`gates.check_code_frozen` for E4), the committed edition, acquisition and mapping records, and the workbook's hash, read-only state and untracked state, and it refuses unless the re-read availability equals the recorded one. It returns counts and hashes for printing (`levels_sha256`, `kinds_sha256`); it prints no level.

## Limits

The stages were developed and tested on constructed pages and constructed workbooks; the layout of the real workbook is not documented (Annex C) and was not seen. Results of the tests are development results (Python 3.12.3); the registered environment is Python 3.12.14 under `requirements.lock`.

## Running the mapping under amendment 1

The first mapping attempt stopped at step 3 (a vintage label does not parse). E4 amendment 1 settles how the vintage labels of the acquired workbook are read (rule A), three header cells read by place (rule B) and the join of its four sheets (rule C); `docs/E4_AMENDMENT_1_CODE.md` maps each sentence of the amendment to the code and its tests, gives the schema of the record and lists the readings taken where the amendment is silent. Once the amendment is registered:

1. Write the amendment record, for example `audit/E4_AMENDMENT_1.json`, with its `label_reading` section (the century pivot, the four codes, the three readings by place and the join rule, exactly as the registered amendment states them), and commit it.
2. Run the mapping again, naming the record:

```text
python tools/acquire_e4.py map --amendment audit/E4_AMENDMENT_1.json
```

The stage checks the record (a malformed section, or a record without the section after a stop at step 1 or 3, is refused before any attempt is recorded), reads the labels under rules A and B, joins the parts under rule C and applies steps 2 to 5 as registered. Besides the registered output it prints, per part, the number of labels by form, the release-month range, the number of reference-quarter rows and the last quarter; the readings by place applied, each with the labels on either side; and the join (the longest part, the rows padded with empty cells per part, the parts in the order of their vintage ranges). The attempt record adds the section applied, these counts and, when the mapping completes, the list of every vintage label with its release month and the rule that read it (`label_readings`, with its SHA-256). No level is read or printed. Compare the printed release-month ranges with those the amendment states, then commit `audit/e4_source/` and `DATA_MANIFEST.csv`. A stop is recorded as before and is settled by a further amendment before any value is read.

3. At X.4, `read_level_tables(root)` takes the amendment from the mapping record (`amendment.record`, whose SHA-256 must match the committed file), reads the labels and joins the parts with the same function as the mapping, and refuses unless the re-read list of labels and release months, and the availability, equal the recorded ones.

The document properties `creator` and `lastModifiedBy` are printed and recorded as "(name withheld)" in every mapping attempt.
