# Registered E4 execution: the X.4 run, its retained record and the X.5 freeze

This document describes steps 4 and 5 of `prereg/E4.md` Annex B for E4 (OSF `dpxqf`), in the style of `docs/E_EXECUTION.md` sections 3 to 5. The code is `src/uc_ext_official/e4_run.py` (the run), `src/uc_ext_official/report_e4.py` (tables, text and figures), `src/uc_ext_official/x4.py` (verification, statement of the result and freeze), `tools/run_e4.py` and `tools/freeze_e.py e4`. Neither step is run by the tests: they exercise every stage on constructed tables, with the development seed and streams and small counts.

## 0. Before X.4

X.4 runs only after `h1-frozen`, after E4's X.2 is complete (edition, acquisition and mapping records committed; the mapping settled by its amendment), and after the X.3 record `audit/E4_X3.json` is committed with passed size and power checks. Every gate below is checked again by the run itself; nothing has to be trusted from an earlier step.

## 1. X.4: run once

```text
python tools/run_e4.py --registered
python tools/run_e4.py --registered --release-dates release-dates.json
```

From a clean checkout under the lock and Python 3.12.14, the command verifies, in this order, and writes nothing until all have passed:

1. code location: `uc_core`, `uc_ext`, `uc_ext_official` and `uc_e4` are imported from the research root's own `src/` (`gates.check_code_location(root, "e4")`);
2. G4 for E4: published registration, tag and protocol record (`gates.check_registration(root, "e4")`);
3. the committed X.3 record with passed official synthetic checks (`gates.check_x3(root, "e4")`);
4. frozen code: E4's code identity equals the one recorded at X.3, and its E1 part equals E1's frozen code identity (`gates.check_code_frozen(root, x3, "e4")`);
5. the output directory: `runs/e4-registered`, not yet existing, git-ignored (`runs/` is in `.gitignore`);
6. the X.2 data: `e4_source.read_level_tables(root)`, which repeats the gates, requires the committed edition, acquisition and mapping records, re-reads the acquired workbook and refuses if the re-read availability differs from the recorded one; the run then checks that the hashes of the cell kinds and levels it receives are the recorded ones;
7. the frozen H1 record `audit/H1_RESULT.json`, committed; its four eligible episodes must be the registered onsets 1973Q3, 1980Q1, 1990Q3 and 2008Q2 (`uc_e4.vintage.load_h1_episodes`), and its SHA-256 is recorded.

It then calls `uc_e4.analysis.analyze` with master seed 1927, the streams of Annex A (5400 primary, Kendall and lag-one; 5401 and 5402 for W = 32 and 48; 5404 wild signs; 5405 episode interval; 5403 unused), B = 1,000 attempts per comparison and 10,000 episode resamples. There are no seed, stream or count options.

`--release-dates` names a JSON object mapping vintage labels to release dates (ISO `YYYY-MM-DD`) established from ONS metadata. Without it, every release is stated by its vintage's label month and the two-clocks table says so (section 10; R-10.5). The dates enter the recorded input and its SHA-256.

The run writes `runs/e4-registered/`:

| File | Contents |
|---|---|
| `run-log.json` | kind (registered primary run or recomputation), commit, code identity and its E1 part, X.3 record and its hash, D80, gate record, environment, package sources, seed, streams, counts, H1 record hash, table summary, input record and its SHA-256, start and finish times and duration. With `RUN_COMPLETE.json`, the only file that carries a time. |
| `analysis.json` | everything `analyze` returns, as canonical JSON with non-finite numbers as null: the selections at W = 40, 32 and 48 (each with its vintage series' growth), the four comparisons with every attempt, every S_b and per-episode change, each episode's fitted null and residuals and the generator states before and after, the six-row table, the episode interval with its resample means, real time against final, the two clocks and the table structure. |
| `report/` | see the next table; `manifest.json` holds the SHA-256 of every other report file. |
| `RUN_COMPLETE.json` | written last: the SHA-256 of `run-log.json`, `analysis.json` and `report/manifest.json`. The run then re-reads every output against these hashes (`x4.complete`). |

A run that stops before `RUN_COMPLETE.json` is written leaves its directory as evidence; `x4.verify_outputs` and the freeze refuse it. It is not deleted and not re-run without a dated decision.

### The retained record (Annex B: "what H1 section 12 lists, plus the availability table, every vintage selection, and each vintage's fitted null and residuals")

| Report file | Numbers |
|---|---|
| `episodes.csv` | one row per H1 eligible episode at W = 40: onset, reference quarter, status and failed step with its reason, v_j and the vintage before it, release date or label month, n_v, Delta_rt and its sign, Delta_final and its sign, their difference (sections 7, 8 and 10) |
| `selections.csv` | every vintage selection at W = 40, 32 and 48: v_j, the run's first quarter and what ended it, number of levels, n_v, section 5 stop and stop note (section 7; R-7.4) |
| `comparisons.csv` | the primary and the five secondary comparisons: status, value, m, k, p labelled "raw, not family-adjusted", requested, attempted, retained, failed, K, B', p grid spacing, q and its Wilson interval (sections 9 and 10) |
| `episode-interval.csv` | status, 90% bounds, episodes, requested and attempted resamples (section 10, as H1 section 7) |
| `real-time-against-final.csv`, `real-time-summary.csv` | the descriptive table of section 10 and its summaries (S_rt, S_final,m, their difference, same-sign count) |
| `two-clocks.csv` | the two clocks of section 10 (SD-07) |
| `availability.csv`, `availability-counts.csv`, `availability-markers.csv` | the kind of every cell (reference quarters by vintages in vintage order), the counts per vintage, and every marker cell with its digits masked; no level |
| `vintage-series.json` | each selected vintage series: run, n_v, growth with its quarters, and the SHA-256 of the run's levels (little-endian float64) |
| `null-models.json` | each compared vintage series' fitted null (phi1, phi2, intercept, initial pair, modulus, removed residual mean) and centred residuals, re-derived and checked against every comparison that used it |
| `rolling.csv` | per compared series and position: growth, the W = 40 rolling fit (intercept, phi1, phi2, modulus, status), the modulus at W = 32 and 48 and the lag-one path |
| `primary-surrogates.csv` | every primary attempt: status, S_b and each episode's Delta_b |
| `report.json`, `report.txt` | all of the above except the availability grid, the rolling fits and the two JSON files, with the outcome at freeze; and a short human-readable statement of the same result |
| `realtime.{svg,png,pdf}`, `surrogates.{svg,png,pdf}` | Delta_rt beside Delta_final for every episode, signed; the primary S_b with S_rt marked. Fixed metadata, so each file is the same bytes for the same inputs; drawn with a note when no episode is E4-eligible |

No level of the vintage table is written by the run: each vintage series is retained as its growth (the section 5 series that every statistic uses) and tied to the acquired workbook by the SHA-256 of its run's levels. The source workbook itself is kept as X.2 recorded it. The report re-derives every primary Delta_rt from the rolling path of its vintage series and every fitted null with `uc_core.surrogate.prepare_null`, and refuses to be written if either disagrees with the analysis.

## 2. X.5: freeze

```text
python tools/freeze_e.py e4
```

The command verifies the registered run against its own hashes, refuses a recomputation, a small-B run on constructed data, an altered or missing output and a second freeze (when `audit/e4/`, `audit/E4_RESULT.json` or any `figures/e4_*` file exists), copies the run log, `RUN_COMPLETE.json`, `analysis.json`, every report file except the figures and the report manifest into `audit/e4/` and the figures into `figures/e4_realtime.*` and `figures/e4_surrogates.*`, verifies every copy and writes `audit/E4_RESULT.json`.

The statement of the result follows section 11 (as H1 section 10 with the Holm-adjusted p in place of the raw p):

- the raw p is reported labelled "raw, not family-adjusted"; the adjusted p is computed at family closure (DR-2) and is null at freeze;
- a raw p above 0.05 is inconclusive whatever Holm does (a Holm-adjusted p is never below its raw p), with the Branch B diagnostic of H1 section 10 as a labelled diagnostic: true only when D80 is defined and the upper end of the 90% episode interval is strictly below D80, and unavailable when D80 or the interval is undefined;
- a raw p at or below 0.05 is pending the family adjustment, and no rejection is declared from it; the "unusually large" statement applies only if the adjusted p at closure is at or below 0.05;
- a failed comparison (including a failed observed statistic) and m_E4 = 0 (not estimable) are recorded as failed and enter DR-2 with Holm input 1;
- D80 comes from the X.3 record (null when undefined);
- the reference is "fixed-date AR(2) surrogates fitted to each episode's first vintage containing the quarter before onset", the statement reports S_rt, every Delta_rt and k/m_E4, and the wording keeps SD-07's limit: E4 measures the revision sensitivity of the H1 statistic in the first vintage that contains the quarter before onset; it is not a test of warning available before the onset quarter began, and the onset dates come from final data.

The frozen files must be stored byte for byte, as E1's and E3's are. `.gitattributes` needs these two lines, beside the E1 and E3 ones, before the frozen files are committed:

```text
audit/e4/** -text
figures/e4_* -text
```

After review, commit and push `audit/e4/`, `audit/E4_RESULT.json` and `figures/e4_*`, update `STATUS.md`, then create and push the tag:

```text
git tag -a e4-frozen -m "E4 registered result frozen" && git push origin e4-frozen
```

## 3. Record-keeping entries made by the owner

- `STATUS.md`: X.4 run (date, commit, code identity, output directory, `RUN_COMPLETE.json` hash) and X.5 freeze (the raw p with its label, the conclusion at freeze, m_E4, the tag).
- `DECISIONS.md`: a dated entry for the freeze, and, when every member of E1 to E4 is frozen, recorded as failed or dropped, the dated family-closure entry with the Holm-adjusted values (section 10).
- `DEVIATIONS.md`: only if a deviation under section 13 arose.

## 4. Recomputation

```text
python tools/run_e4.py --registered --recomputation --output-directory runs/e4-recomputation-<date>
```

A recomputation for verification passes the same gates, must use the same inputs, software and streams, writes to its own new directory, is labelled "recomputation" in its run log and is never frozen (H1 section 10; D-039).

## 5. Small-B run on constructed data

`e4_run.small_b_run_e4(tables, h1_episodes, output, B=..., interval_B=..., h1_sha256=...)` runs the whole chain on `uc_e4.table.Tables` built from arbitrary numbers, with the development seed and streams, passes no gate, labels every output a small-B run on constructed data and can never be frozen. `tests/test_e4_run.py`, `tests/test_e4_report.py` and `tests/test_e4_freeze.py` build such tables (B = 20, 100 resamples) and exercise every output, gate refusal and freeze refusal; the registered path is exercised there with every gate replaced and with `analyze` replaced by a check that it is asked for exactly the registered computation. Results on any machine other than the registered environment (Python 3.12.14 under the lock) are development results.
